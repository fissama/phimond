# `.ai/reviews/` — gameplay & game design reviews per phase

Per-phase retrospective. Cross-references from
`plan/phases/PXX/PXX-gameplay-gamedesign-review.md` should also live here
(or move there entirely; pick one home per phase and link from the other).

## Index

| Phase | File | Date |
| ----- | ---- | ---- |
| P00   | `P00-review.md` | 2026-09-23 |

## Structure

Each review follows the template in `SPRINT_SPEC_TEMPLATE.md → "Mẫu report
review của phase"`. Key sections:

1. **Phạm vi / baseline** — what was in scope, baseline state, reference.
2. **Review đầu phase** — initial hypothesis, friction, design gap.
3. **Các vòng review trong phase** — sprint-by-sprint changes + measures.
4. **Finding / decision log** — ID, severity, evidence, owner, target.
5. **Review cuối phase** — exit-gate verdict, regression check, visual debt.
6. **Kết luận** — đạt / chưa đạt exit gate, blockers, re-review condition.

## When to write

- After each phase closes (mandatory).
- After a sprint if the user wants an interim review.

## When NOT to write

- For ad-hoc design tweaks (commit message or ADR is enough).
